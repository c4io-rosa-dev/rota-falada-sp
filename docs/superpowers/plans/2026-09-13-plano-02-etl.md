# Plano 2 — ETL das fontes oficiais: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Popular o PostGIS da área piloto (Vila Mariana, Lapa, Ipiranga/FATEC) com o grafo de pedestres do OpenStreetMap, as calçadas do GeoSampa, as reclamações do SP156 e as paradas/linhas do GTFS da SPTrans, por meio de um ETL reexecutável em Docker e agendado no GitHub Actions, com testes de qualidade de dados que falham o job.

**Architecture:** Pacote Python `etl/` independente do backend (mesmo banco, esquema criado por migrations Alembic do backend). Roda dentro do container `etl` do docker-compose (imagem própria com `osmium-tool`), idêntico ao runner do GitHub Actions. Cada fonte é um módulo com função `executar(engine) -> ResultadoEtl`; o orquestrador grava uma linha em `etl_execucao` por fonte. O grafo do OSM é montado com `osmium` (recorte e filtro de tags) + `osmnx.graph_from_xml` (topologia) e carregado com GeoPandas; **não usamos `osm2pgsql`** porque ele não divide as vias nos cruzamentos, e o pgRouting precisa de `source`/`target` por aresta (registrar em `docs/adr/002-grafo-com-osmnx.md`).

**Tech Stack:** Python 3.12 (no container), osmium-tool, osmnx ≥ 2.0, GeoPandas + pyogrio, Shapely 2, pyproj, pandas, requests, SQLAlchemy 2 + GeoAlchemy2, psycopg 3, pytest. Docker Compose (perfil `etl`). GitHub Actions com cron.

**Nível de detalhe deste plano:** as tarefas trazem interfaces, esquema SQL, testes e o código dos pontos críticos (classificação de `kerb`, custo, paginação do WFS, leitura cp1252). O código de cola (leitura de CSV, inserção com GeoPandas) fica a cargo do implementador, que deve seguir o mesmo estilo do Plano 1.

## Global Constraints

- Tudo do Plano 1 continua valendo (Python ≥ 3.12, SRID 4326 no banco, métrica em EPSG:31983, nenhuma chave versionada, sem IA, repositório público).
- **Toda tabela espacial carrega `fonte_id` (FK para `fonte_dados`), `data_referencia` e `geom` em SRID 4326.**
- **`calcada_sp` (CC-BY-SA) e `via_pedestre` (ODbL) nunca trocam atributos**; a ligação será a tabela de junção do Plano 3.
- **Zeros do GeoSampa são ausência, não medição**: colunas geradas `largura_medida` e `declividade_medida`.
- **`kerb=yes` significa "existe guia de altura indeterminada"** e grava `NULL` em `kerb_transponivel`. Nunca é acessível.
- Overpass **não** é usada em nenhum script do ETL. Dados brutos (`*.pbf`, `*.zip`, `*.csv`) vão para `etl/dados/`, que está no `.gitignore`.
- Área piloto (bbox em lon/lat, oeste,sul,leste,norte):
  - Vila Mariana: `-46.660,-23.610,-46.615,-23.570`
  - Lapa: `-46.720,-23.545,-46.680,-23.510`
  - Ipiranga / FATEC: `-46.625,-23.605,-46.590,-23.575`
- Todo download valida tamanho e é cacheado em `etl/dados/` (reutilizado se tiver menos de 7 dias), para o ETL ser reexecutável sem baixar 817 MB de novo.
- Nenhum script lê `.env` da raiz diretamente; a URL do banco vem da variável `DATABASE_URL` (no compose e no Actions).

### Task 3: ETL do OpenStreetMap → `no_pedestre` e `via_pedestre`

**Files:**
- Create: `etl/etl/osm.py`
- Modify: `etl/etl/cli.py` (subcomando `osm`)
- Test: `etl/tests/test_qualidade_dados.py` (parte OSM; integração)

**Interfaces:**
- `etl.osm.executar(engine, *, pbf: Path | None = None) -> dict` com `{'nos': int, 'vias': int}`. Se `pbf` for dado, pula o download (usado nos testes com um recorte pequeno).
- Pipeline, nesta ordem:
  1. `baixar(URL_GEOFABRIK, DIR_DADOS/'sudeste-latest.osm.pbf', tamanho_minimo=500_000_000)`.
  2. `osmium extract --bbox <BBOX_UNIAO> -s smart sudeste-latest.osm.pbf -o piloto.osm.pbf` (bbox união dos três recortes; `-s smart` mantém vias completas que cruzam a borda).
  3. `osmium tags-filter piloto.osm.pbf w/highway -o piloto-vias.osm.pbf` (mantém os nós referenciados).
  4. `osmium cat piloto-vias.osm.pbf -o piloto-vias.osm` (XML, exigido pelo osmnx).
  5. `osmnx`: `settings.useful_tags_way = ['highway','footway','sidewalk','wheelchair','surface','smoothness','width','incline','name','foot','access','step_count','ramp','ramp:wheelchair','crossing','tactile_paving','lit']`, `settings.useful_tags_node = ['highway','kerb','tactile_paving','crossing','wheelchair','barrier']`; `G = ox.graph_from_xml(caminho, bidirectional=True, simplify=False, retain_all=True)`; remover arestas onde `not eh_via_de_pedestre(tags)`; `G = ox.simplification.simplify_graph(G, edge_attrs_differ=['highway','footway','sidewalk','wheelchair','surface','smoothness','width','incline','name'])`; `nos, arestas = ox.graph_to_gdfs(G)`.
  6. Só arestas com `u < v` ou sem par reverso (o grafo é bidirecional; grava-se uma aresta por par, `custo_reverso = custo_acessivel`).
  7. Por aresta: `kerb, kerb_transponivel = classificar_kerb([nos.loc[u,'kerb'], nos.loc[v,'kerb']])`; `esquema_calcada`; `is_degrau = highway == 'steps'`; `comprimento_m` em 31983; `custo_acessivel = comprimento_m * fator_custo(tags, kerb_transponivel)`; `width_m` = float de `width` quando parseável (aceitar "1.5", "1,5", "1.5 m"; senão NULL).
  8. Recorte final: manter só nós e arestas que intersectam a união das três `area_piloto` (o `-s smart` traz sobras).
  9. Carga: `DELETE FROM via_pedestre; DELETE FROM no_pedestre;` na mesma transação, depois `to_postgis(..., if_exists='append')` de nós e depois arestas, com `fonte_id = fonte_id(engine,'osm')` e `data_referencia` = data do `Last-Modified` do PBF (ou data de hoje se ausente).
  10. `registrar_execucao/concluir_execucao('osm', linhas=vias)`.
- Se osmnx aceitar apenas listas em atributos (tags que variaram na simplificação), converter para o primeiro valor.

### Task 4: ETL do GeoSampa → `calcada_sp` (WFS paginado sem truncamento)

**Files:**
- Create: `etl/etl/geosampa.py`
- Modify: `etl/etl/cli.py` (subcomando `geosampa`)
- Test: `etl/tests/test_geosampa_paginacao.py` (unitário), `test_qualidade_dados.py` (parte GeoSampa)

**Interfaces:**
- `etl.geosampa.contar(bbox) -> int` (GetFeature com `resultType=hits`, lê `numberMatched`).
- `etl.geosampa.paginar(bbox, count=2000, sessao=None) -> Iterator[dict]` (GeoJSON features), com `startIndex` explícito, `sortBy=cd_identificador_calcada` (paginação WFS 2.0 exige ordenação estável), pausa de 1 s entre páginas, e **verificação**: soma de `numberReturned` == `numberMatched`; caso contrário `TruncamentoWFS` (exceção própria).
- `etl.geosampa.executar(engine) -> dict` com `{'calcadas': int, 'esperado': int}`; roda para cada uma das três bboxes; dedup por `cd_identificador_calcada`.
- Requisição (uma por página):

```
GET https://wfs.geosampa.prefeitura.sp.gov.br/geoserver/geoportal/wfs
  ?service=WFS&version=2.0.0&request=GetFeature
  &typeName=geoportal:calcada
  &outputFormat=application/json
  &srsName=EPSG:4326
  &bbox=<oeste>,<sul>,<leste>,<norte>,EPSG:4326
  &count=2000&startIndex=<n>&sortBy=cd_identificador_calcada
```
- Mapeamento de propriedades → colunas: `qt_largura_minima_trecho→largura_min_m`, `qt_largura_maxima_trecho→largura_max_m`, `qt_largura_media_trecho→largura_media_m`, `pc_declividade_minima_trecho→declividade_min_pct`, `pc_declividade_maxima_trecho→declividade_max_pct`, `pc_declividade_media_trecho→declividade_media_pct`, `qt_area_calcada→qt_area_m2`, demais pelo nome.
